# Opinion Manager（Agent 行为规则管理）

## 定位

把用户确认的表达方式、协作方式、判断标准、交付要求和开发规范整理为一份可人工编辑的 `OPINION.md`。模板只提供候选规则；用户确认后的 `OPINION.md` 是当前环境的权威内容。

保持职责边界：

- `agents-init` 创建或迁移项目契约，并触发 Opinion 配置；
- `opinion-manager` 管理 Opinion 的生成、组合、审查和演化；
- `project-orchestrator` 管理 Task/Case、文件位置、验证编排与 Git 交付；
- `agent-pack` 管理 Plugin、Skill 与 MCP。

禁止根据一次对话自动形成长期规则。新增、删除或改变规则适用范围前，必须展示最终内容并取得用户确认。

## 三种配置模式

### 自定义生成

用户粘贴既有 `AGENTS.md`、规则文件或自然语言说明时使用。

1. 提取明确要求，区分强制规则、偏好、项目事实和一次性任务。
2. 只把 Agent 行为、表达、判断与交付要求写入 Opinion。
3. 项目命令、目录、依赖和权限约束留在 `AGENT.RULES.md`。
4. 标出冲突、重复规则和缺少适用范围的条目。
5. 展示清理后的完整 `OPINION.md`，经用户确认后写入。

用户可以不提供任何内容，也可以明确跳过 Opinion 配置。

### 模板组合

用户希望快速配置时使用。读取 `../../templates/*.json` 中已经公开并经过用户批准的模板说明和版本。模板格式遵循 [template.schema.json](../../references/template.schema.json)：

1. 展示模板名称、适用场景、版本和简短说明。
2. 允许选择一个或多个模板。
3. 使用 `runtime/opinion_manager.py compose` 生成预览；相同规则编号自动去重，内容不同的相同编号立即终止。
4. 展示合并后的完整内容。
5. 用户确认后追加 `--apply` 写入 `OPINION.md`。

公开模板目录当前可以为空。没有已批准模板时，明确说明模板组合暂不可用，继续提供自定义生成或跳过配置；禁止临时生成模板并写入公开目录。

### 引导选择

用户希望逐条控制时使用。

1. 从模板的 `questions` 字段选择与当前目标相关的问题。
2. 根据回答推荐具体规则，并说明规则编号、内容和适用场景。
3. 逐条记录用户的保留或排除决定；未确认条目不写入。
4. 使用 `--rule` 传入已确认的规则编号，生成统一预览。
5. 用户确认完整文件后写入。

引导问题用于缩小候选范围，不能代替用户确认。

公开模板目录为空时，引导选择模式也暂不可用。

## 确定性工具

模板目录与合并由 `../../runtime/opinion_manager.py` 处理：

```bash
python3 ../../runtime/opinion_manager.py catalog --output markdown
```

预览一个或多个完整模板：

```bash
python3 ../../runtime/opinion_manager.py compose \
  --project /path/to/project \
  --template TEMPLATE_ID@VERSION
```

逐条选择：

```bash
python3 ../../runtime/opinion_manager.py compose \
  --project /path/to/project \
  --rule RULE_ID
```

自定义生成模式中，用户已经提供本地规则文件时可以通过 `--custom-file` 合并。规则来自当前对话时，直接用文件编辑工具写入用户确认后的完整 `OPINION.md`，禁止为了调用工具再创建含相同个人内容的中间副本。所有工具写入默认预演；用户确认后追加 `--apply`。现有 `OPINION.md` 含真实规则时还需要 `--replace`，已知的 agents-init 空白占位文件可以直接替换。

## 文件契约

最终只生成一份 `OPINION.md`。文件包含：

- 机器可读的模板版本、已选择规则编号和生成时间；
- 用户可直接阅读和编辑的规则正文；
- 每条模板规则的稳定编号；
- 用户自定义规则正文。

人工修改后的文件继续有效。后续重新生成前读取当前文件、预览完整差异，并保留用户仍然确认的自定义内容。

用户粘贴的个人规则只用于生成其当前环境的 `OPINION.md`，禁止复制到公开模板目录、示例、测试或文档。

## 公开模板准入

公开模板必须由用户明确提出或提供内容，并依次完成：

1. 确认模板名称、适用场景、目标用户和不适用范围。
2. 为模板和每条规则分配稳定编号与版本。
3. 检查个人信息、私有路径、组织信息、凭据和敏感行为偏好。
4. 检查规则之间的冲突、重复、可执行性和适用范围。
5. 使用独立测试样例验证组合、逐条选择、版本记录和冲突处理。
6. 向用户展示将要公开的完整模板文件。
7. 取得用户对该完整内容的明确同意后再加入公开目录。

对已有模板的内容修改同样需要完整预览和用户明确同意。只调整拼写且不改变含义时，也要在发布前展示最终文件。

## 指导与审查

项目声明 `provider: opinion-manager` 时：

1. 实施前读取 `OPINION.md`，只选择与当前任务范围匹配的规则。
2. 交付前逐项检查适用规则，直接修正可以确定的问题。
3. 规则冲突会改变交付物时，列出冲突规则编号并请用户裁定。
4. 用户反馈可能形成长期规则时，提交候选内容、适用范围和来源，确认后更新文件。

Opinion 只指导和审查交付物，不创建 Task/Case，不修改项目进度，不执行 Git 操作。

## 完成条件

- 已明确使用自定义生成、模板组合、引导选择或跳过；
- 已展示最终完整内容；
- 只有用户确认的规则进入 `OPINION.md`；
- 模板版本、规则编号和自定义内容可追溯；
- 文件写入后重新读取并核对；
- 没有修改项目生命周期、能力清单或 Git 状态。
